# Mind+ 旋转编码器扩展库

用于 **Mind+ 1.x → 上传模式 → Arduino C**，支持 **Arduino Uno / Uno R3、掌控板（mPython，经典 ESP32）**。依照用户提供的 [Mind+ 1.x 扩展库接口](https://mindplus.dfrobot.com.cn/ext-api) 制作。Mind+ 2.x 使用不同的扩展接口，本包不是 2.x 扩展。

版本：1.0.2。无需额外安装第三方 Arduino 库。当前支持一个旋转编码器。

## 1. 适用模块及接线

根据实物照片和“一个 3P SVG、一个 4P SSVG”的描述，本库按下列接口实现：

- **4P 口 S/S/V/G**：两个 S 分别是机械编码器 A、B 两路正交数字信号；在本文中暂称 S1、S2。
- **3P 口 S/V/G**：S 是按压开关信号，低电平表示按下。
- V 是电源，G 是地。两个接口的电源和地通常共用，具体以模块电路为准。

**上述信号功能是依据接口形式作出的接线假设，尚未由模块型号或实测确认。** 如果模块输出不是 A/B 正交脉冲，或 3P 的 S 不是低电平按键，需要按真实协议调整驱动。请按模块上 S/V/G 字母辨认接点，不按照片方向或线色猜测。

| 模块接口 | Arduino Uno 默认接线 | 掌控板默认接线 |
|---|---|---|
| 4P 第一个 S（S1/A） | D2 | P0 |
| 4P 第二个 S（S2/B） | D3 | P1 |
| 3P S（按键） | D4 | P8 |
| V | 5V（模块须支持 5V） | 3.3V（模块须支持 3.3V） |
| G | GND | GND |

掌控板信号脚为 **3.3V 电平，不能接入 5V 信号**。若此模块只支持 5V，需使用合适的电平转换后再接掌控板。不要把 Uno 的 5V 电源和掌控板的 3.3V 电源相连。

只有旋转功能时，3P 口可不连接，初始化积木的按键引脚选“不连接”。使用掌控板时通常需要能引出 P 引脚的扩展板；选用扩展板上的 3.3V 电源。

Uno 的旋转输入使用 D2、D3 两个外部中断脚；允许交换它们。按键可选 D4～D13 或 A0～A5。掌控板可选 P0、P1、P6、P7、P8、P9、P13、P14、P15、P16；三个信号脚不能重复。已排除无内部上拉的 P2/P3/P4/P10、板载按键及板载 I²C 引脚，避免常见冲突；仍需避开项目中已被其他模块占用的脚。

掌控板映射取自本机 Mind+ 的 `variants/mpython/pins_arduino.h`：P0→GPIO33、P1→GPIO32、P6→GPIO16、P7→GPIO17、P8→GPIO26、P9→GPIO25、P13→GPIO18、P14→GPIO19、P15→GPIO21、P16→GPIO5。积木显示 P 编号，生成代码使用 GPIO 编号；不要把 GPIO33 当成 P33。

## 2. 导入 Mind+

1. 解压 `MindPlus-RotaryEncoder-1.0.2.zip`，保留整个文件夹结构。在开发工作区中，发布包位于 `releases/rotary-encoder/`。
2. 在 Mind+ 1.x 切换到“上传模式”，选择 Arduino Uno 或掌控板。
3. 打开“扩展 → 用户库 → 导入用户库／从本地导入”（名称随版本可能略有差异）。
4. 选择解压目录中的 **config.json**。不要只复制这个 JSON，旁边的 arduinoC 文件夹也需要保留。
5. 加载后出现“旋转编码器（旋转与按压）”。从本地 config.json 加载会显示调试标志，这是正常现象。

本包提供源码 ZIP 和 config.json 导入入口。需要 `.mpext` 时，在 Mind+ 成功加载后右键扩展库选择“导出用户库”；不要直接将 ZIP 改后缀充当正式导出包。

## 3. 积木说明

| 积木 | 含义 |
|---|---|
| 初始化编码器 4P口 S1…S2…3P口 S… | 放在“当开始运行”下，初始化并把计数清零。按键可选不连接。 |
| 编码器初始化成功？ | 引脚有效且初始化完成时为真；不能检测模块是否实际插入。 |
| 编码器当前计数 | 有符号累计步数，初始 0，反转可变为负数。读取不清零。 |
| 编码器计数设为… | 设为 0 即归零，也可设置其他整数；同时清除变化量、最后方向和未完成的半步。 |
| 编码器读取并清除变化量 | 返回自上次读取以来的净变化，读取即清除；建议每轮读取一次存入变量。 |
| 编码器最后方向（正转1 反转-1） | 返回最后一次完成计步的方向；停止旋转后仍保留。初始化或归零后为 0。 |
| 编码器计数方向 正常/反转 | 调整正负方向；已有计数不变。 |
| 编码器每格信号变化次数 4/2/1 | 默认 4。适配不同脉冲数的机械旋钮，1 为原始边沿计数，抗抖效果较弱。 |
| 更新编码器按键状态 | 放在“重复执行”中，采样按键并完成 20ms 消抖。 |
| 编码器按键按住？ | 返回消抖后的持续状态；读取时也会更新采样。 |
| 编码器按键新按下？（读取后清除） | 每次消抖后的按下事件返回一次真，长按不反复触发；读取后清除。 |

“最后方向”表示历史方向，不表示现在是否正在转动。判断本轮是否转动，请读取“变化量”到变量，再与 0 比较。正转/反转由 A/B 接线决定；如果希望顺时针递增而实物表现相反，设置“反转”即可。

## 4. 第一个积木程序：旋转计数，按下归零

```text
当开始运行
    初始化编码器 4P口 S1 D2  S2 D3  3P口 S D4
    [掌控板改选 P0、P1、P8]

重复执行
    更新编码器按键状态
    如果 编码器按键新按下？（读取后清除）
        编码器计数设为 0
    使用串口或屏幕显示“编码器当前计数”
    等待 0.001 秒
```

串口或屏幕输出建议用计时器限制为每 100ms 一次，其余循环继续更新按键。在掌控板 Mind+ 项目中可使用自带 OLED 积木显示计数。公开示例见 `examples/MindPlus/编码器示例程序.mp`；Arduino 验证草图仅在开发者本地保留。

**旋转通过中断采集**，普通 `delay()` 期间仍能计数；如果其他库长时间关闭中断，或输入脉冲过快，仍可能漏计。本库用于手动旋钮，不用于高速电机位置反馈。

**按键通过循环采样**，建议每 1～5ms 更新一次，避免在循环中长时间等待。若一次按下和释放全部发生在程序阻塞期间，无法捕获该短按。未消费的按下事件用一个标志保存，多次事件会合并，不是队列。

初始化只执行一次。需要改变方向或每格计数时，将对应设置放在初始化之后；再次初始化会恢复方向“正常”、每格 4 次变化、计数 0。

## 5. 实物调试

1. 先确认“初始化成功”为真，检查两路 S、V、G 的实际标识。
2. 慢转 10 格。如果计数只变化 5，试设每格 2 次变化；如果变化 20，检查当前是否设成了 2，改回 4。机械档位与电气周期不一定一一对应，需要实物校准。
3. 顺逆方向相反时使用“反转”积木，或者断电后交换两个 S。
4. 按下后计数应归零；长按只触发一次。没有按键响应时检查 3P 信号功能、共地以及循环采样频率。
5. 输入全无变化时先核实这块模块确实提供 A/B 正交信号，而不是已处理的单脉冲/方向信号。不要仅凭 SSVG 的字母认定协议。

## 6. 验证与限制

2026-10-23 的软件验证记录见 `VALIDATION.md`。包含 Uno 编译、Mind+ 自带掌控板核心编译、解码与按键模拟测试及积木生成器测试。

用户已反馈导入成功，并提供了保存的 .mp 项目及导出的 1.0.2 .mpext。代理未完成界面内完整拖拽验收，尚未连接照片中的实物做转动和按压测试，因此不能将编译通过等同于该型号实物验证通过。

本库不占用定时器；Uno 使用 D2/D3 外部中断。编码器对象应为全局对象，所有方法从 Arduino 主循环任务调用，不从其他中断或多个 ESP32 任务并发调用。32 位计数到边界后饱和，不回绕。读取计数/变化量时使用 AVR 中断状态保护或 ESP32 临界区，避免读到撕裂的数据。

## 开发文件

- `config.json`：Mind+ 扩展配置。
- `arduinoC/main.ts`：中文积木及代码生成器。
- `arduinoC/_menus/`：不同主控的引脚下拉菜单。
- `arduinoC/libraries/MindPlusRotaryEncoder/`：驱动源码。
- `examples/`：Arduino 串口计数、按下归零示例。
- `tests/`：主机端驱动逻辑与生成器测试。
- `tools/package.py`：校验现有封面并生成可解压导入的 ZIP，不会覆盖封面。
